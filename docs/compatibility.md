# Compatibility

What to install next to which version of HDDS: the code generator, the language
SDKs, the ROS 2 middleware layer and the Rust toolchain.

## Supported versions

Pairing of `hdds` with the code generator:

| hdds version | hddsgen version | CODEGEN_ABI | Notes |
|---|---|---|---|
| 1.5.0 | 2.0.0 or later | runtime provides 1 | A generator that emits the guard requires `>= 1`, see below |

Toolchains and platforms:

| Component | Version | Notes |
|---|---|---|
| Rust toolchain | Recent stable; 1.90 builds the `hdds` crate, 1.85 does not | Needed to build the core library, also for C, C++ and Python projects that build HDDS from source. The workspace uses edition 2021 and does not declare a separate minimum version (`rust-version`); the core uses `is_multiple_of` on integers, which 1.85 rejects. Versions between 1.85 and 1.90 have not been tried |
| C++ SDK | C++17 | CMake 3.16 or later |
| Python SDK | Python 3.9 or later | Pure Python, loads the native library at run time |
| TypeScript SDK | Node.js 18 or later | |
| ROS 2 (`rmw_hdds`) | Humble, Iron, Jazzy | Humble: ten-round RMW comparison on record (see [ROS 2 Performance](ros2/performance.md)). Iron, Jazzy: builds expected, no recorded run. See [ROS 2 integration](ros2-integration.md) |

Standards the `hdds` crate implements, as stated in the repository README:

| Standard | Version | Scope |
|---|---|---|
| DDS | 1.4 | Publish-subscribe API, QoS policies |
| RTPS | 2.4 on the wire | Announced as protocol version 2.4; any 2.x peer is accepted |
| XTypes | 1.3 | TypeIdentifier / TypeObject, type compatibility checking and type announcement in discovery |
| DDS Security | 1.1 | HDDS-to-HDDS only; cross-vendor security interoperability is not covered |

Platforms: Linux (tested); Windows: cross-built, test suites run on Windows 11
and under Wine, with known test-portability failures; macOS: tested natively
on macOS 14 (x86_64), Apple Silicon not yet tested.

Other DDS implementations: the interoperability checks run against Eclipse
Cyclone DDS, eProsima Fast DDS and OpenDDS, with the versions listed in the
[interoperability overview](interop/index.md). No other vendor version is
claimed here.

## hdds and the code generator

Two artifacts have to agree:

- **hdds**, this repository. The `hdds` crate is what generated code links
  against at build time and calls into at run time.
- **hddsgen**, the IDL code generator, which lives in its own repository
  (`https://git.hdds.io/hdds/hdds_gen.git`) and installs a binary named
  `hddsgen`. It is **not** `tools/hdds-gen` of this workspace: that crate is a
  different tool and does not provide `hddsgen`
  ([Installing hdds_gen](tools/hdds-gen/installation.md)).

HDDS 1.5 expects code generated by **hddsgen 2.0 or later**. Older generators
emit FINAL instead of APPENDABLE for types without an extensibility annotation
(`hddsgen` 2.0 prints a notice, and `--default-extensibility final` restores the
old layout). Regenerate your types after upgrading.

### The `CODEGEN_ABI` guard (Rust generated code)

Generated code calls into `hdds` internals that are not part of the crate's
stable public API. `hdds::codegen::CODEGEN_ABI` (`crates/hdds/src/codegen.rs`)
is a `u32` that `hdds` bumps when such an internal shape changes
incompatibly. A generator that requires a given number emits, once per
generated Rust file, a compile-time assertion:

```rust
const _: () = assert!(
    hdds::codegen::CODEGEN_ABI >= 1,
    "this file was generated by hddsgen for hdds::codegen::CODEGEN_ABI >= 1 \
     (hdds >= 1.5.0); the linked `hdds` crate is older or incompatible - \
     upgrade the `hdds` dependency to >= 1.5.0",
);
```

The comparison is `>=`, so a later `hdds` that bumped the ABI further still
accepts code generated for an older number. On a runtime that carries the
constant with a lower number, the assertion fails to compile and names the
required version. A runtime older than 1.5.0 has no `hdds::codegen` module at
all: rustc then reports unresolved imports and `could not find codegen in
hdds`, which does not name the fix, so upgrade `hdds` to 1.5.0 or later. The
guard costs nothing at run time.

The guard covers generated **Rust** code only. The C, C++, Python, TypeScript
and embedded backends emit no compatibility assertion: regenerate their output
whenever you upgrade `hdds`.

To check which side carries what:

```bash
# what the runtime provides
grep -n 'pub const CODEGEN_ABI' crates/hdds/src/codegen.rs
# what your generated file demands (no line means: generated without the guard)
grep -n 'CODEGEN_ABI' your_generated.rs
```
