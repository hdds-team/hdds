# Cross-Vendor Example

Demonstrates HDDS publishing to subscribers built with other DDS implementations.

## Overview

HDDS speaks standard RTPS (it announces protocol version 2.4) over UDP. The
[Interoperability Guide](../interop/index.md) reports the results of a
reproducible run against these implementations and versions:

- **Fast DDS** (eProsima) 3.6.2
- **Cyclone DDS** (Eclipse) 11.0.1
- **OpenDDS** 3.34.0

Other versions of these projects, and other implementations, are not covered by
that run. A setup guide for RTI Connext is available; no results are published
for it.

## Common IDL Definition

All vendors must generate their types from the same IDL, so that the type
name (`interop::Message`), the member names and the key are identical:

```c title="Interop.idl"
module interop {
    @topic
    struct Message {
        @key unsigned long sender_id;
        unsigned long long seq_num;  // "sequence" is an IDL keyword
        string<256> content;
        float values[4];
    };
};
```

Generate the HDDS types with `hddsgen` (built from the separate `hdds_gen`
repository: `git clone https://git.hdds.io/hdds/hdds_gen.git && cargo install --path hdds_gen`):

```bash
hddsgen gen rust Interop.idl -o src/interop.rs
```

Declare the generated file as a module of the package. The HDDS program below
refers to the package as `my_app`; use your own package name:

```rust title="src/lib.rs"
pub mod interop;
```

The IDL module `interop` becomes the Rust module `interop::interop`, and the
generated type reports the wire type name `interop::Message`. Each other vendor
generates its own types from the same file (`fastddsgen Interop.idl`,
`idlc -l c Interop.idl`).

## HDDS Publisher

```rust title="src/bin/hdds_publisher.rs"
use hdds::{Participant, QoS, TransportMode};
use my_app::interop::interop::Message;
use std::time::Duration;

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let participant = Participant::builder("hdds_publisher")
        .domain_id(0)
        .with_transport(TransportMode::UdpMulticast)
        .build()?;

    let topic = participant.topic::<Message>("InteropTopic")?;

    // Use standard QoS for maximum compatibility
    let writer = topic
        .writer()
        .qos(QoS::reliable().keep_last(10).transient_local())
        .build()?;

    // Wait for at least one matched reader (any vendor)
    while writer.matched_reader_count() == 0 {
        std::thread::sleep(Duration::from_millis(100));
    }

    for seq_num in 1..=100 {
        let msg = Message {
            sender_id: 1, // HDDS sender
            seq_num,
            content: format!("Hello from HDDS #{}", seq_num),
            values: [1.0, 2.0, 3.0, 4.0],
        };

        writer.write(&msg)?;
        println!("HDDS sent: {}", msg.content);
        std::thread::sleep(Duration::from_millis(100));
    }

    Ok(())
}
```

## Fast DDS Subscriber (C++)

Written for Fast DDS 3.x, with the types generated by `fastddsgen Interop.idl`:

```cpp title="fastdds_subscriber.cpp"
#include <chrono>
#include <iostream>
#include <thread>

#include <fastdds/dds/domain/DomainParticipant.hpp>
#include <fastdds/dds/domain/DomainParticipantFactory.hpp>
#include <fastdds/dds/subscriber/DataReader.hpp>
#include <fastdds/dds/subscriber/DataReaderListener.hpp>
#include <fastdds/dds/subscriber/SampleInfo.hpp>
#include <fastdds/dds/subscriber/Subscriber.hpp>
#include <fastdds/dds/topic/Topic.hpp>
#include <fastdds/dds/topic/TypeSupport.hpp>

#include "Interop.hpp"
#include "InteropPubSubTypes.hpp"

using namespace eprosima::fastdds::dds;

class MessageListener : public DataReaderListener {
public:
    void on_data_available(DataReader* reader) override {
        interop::Message msg;
        SampleInfo info;

        while (reader->take_next_sample(&msg, &info) == RETCODE_OK) {
            if (info.valid_data) {
                std::cout << "Fast DDS received: " << msg.content()
                          << " (seq_num=" << msg.seq_num() << ")" << std::endl;
            }
        }
    }
};

int main() {
    auto factory = DomainParticipantFactory::get_instance();
    auto participant = factory->create_participant(0, PARTICIPANT_QOS_DEFAULT);

    // Register type
    TypeSupport type(new interop::MessagePubSubType());
    type.register_type(participant);

    // Create subscriber and topic
    auto subscriber = participant->create_subscriber(SUBSCRIBER_QOS_DEFAULT);
    auto topic = participant->create_topic("InteropTopic", type.get_type_name(),
                                           TOPIC_QOS_DEFAULT);

    // QoS must match HDDS
    DataReaderQos reader_qos = DATAREADER_QOS_DEFAULT;
    reader_qos.reliability().kind = RELIABLE_RELIABILITY_QOS;
    reader_qos.durability().kind = TRANSIENT_LOCAL_DURABILITY_QOS;
    reader_qos.history().kind = KEEP_LAST_HISTORY_QOS;
    reader_qos.history().depth = 10;

    MessageListener listener;
    auto reader = subscriber->create_datareader(topic, reader_qos, &listener);

    std::cout << "Fast DDS waiting for messages..." << std::endl;
    std::this_thread::sleep_for(std::chrono::seconds(60));

    return 0;
}
```

## Cyclone DDS Subscriber (C)

```c title="cyclone_subscriber.c"
#include <inttypes.h>
#include <stdio.h>

#include "dds/dds.h"
#include "Interop.h"

int main(void) {
    dds_entity_t participant = dds_create_participant(0, NULL, NULL);
    dds_entity_t topic = dds_create_topic(
        participant, &interop_Message_desc, "InteropTopic", NULL, NULL);

    // QoS matching HDDS
    dds_qos_t *qos = dds_create_qos();
    dds_qset_reliability(qos, DDS_RELIABILITY_RELIABLE, DDS_SECS(1));
    dds_qset_durability(qos, DDS_DURABILITY_TRANSIENT_LOCAL);
    dds_qset_history(qos, DDS_HISTORY_KEEP_LAST, 10);

    dds_entity_t reader = dds_create_reader(participant, topic, qos, NULL);
    dds_delete_qos(qos);

    printf("Cyclone DDS waiting for messages...\n");

    interop_Message *msg = interop_Message__alloc();
    dds_sample_info_t info;

    while (1) {
        void *samples[1] = { msg };
        int32_t n = dds_take(reader, samples, &info, 1, 1);

        if (n > 0 && info.valid_data) {
            printf("Cyclone received: %s (seq_num=%" PRIu64 ")\n",
                   msg->content, msg->seq_num);
        }
        dds_sleepfor(DDS_MSECS(10));
    }

    return 0;
}
```

## Wire-Level Compatibility

HDDS announces RTPS 2.4 in its message headers and uses the standard SPDP/SEDP
discovery, reliable (HEARTBEAT/ACKNACK) delivery and DATA_FRAG fragmentation.
The protocol version a peer announces differs between implementations (the
[Interoperability Guide](../interop/index.md) lists the versions seen in the
packet captures of the reference run), and the participants still interoperate.
The submessages, encapsulation identifiers and built-in endpoints HDDS
implements are listed in [Wire Compatibility](../interop/wire-compatibility.md).

### Data Representation

A writer offers one data representation: XCDR1 by default, XCDR2 when its QoS
asks for it (`QoS::reliable().data_representation_xcdr2()`). A reader requests
both XCDR1 and XCDR2 unless its QoS restricts the list
(`data_representation_xcdr1()` / `data_representation_xcdr2()`). Match the
representation the other vendor's endpoint offers or requests when you see
no data.

## Troubleshooting Interop

### Discovery Issues

```bash
# Verify RTPS discovery traffic (domain 0 uses UDP port 7400 for SPDP multicast)
tcpdump -i any -n udp port 7400
```

HDDS logs through the Rust `log` crate. To see its discovery logs, initialise a
logger in your program (for example `env_logger::init()`) and run with:

```bash
export RUST_LOG=hdds=debug
```

### QoS Mismatch

Common incompatibilities:

| Issue | Symptom | Solution |
|-------|---------|----------|
| Reliability mismatch | No data received | A BestEffort writer does not match a Reliable reader: match Reliable/BestEffort |
| Durability mismatch | Late joiner gets no data | Writer durability must be at least the reader's |
| Data representation | No match | Align XCDR1/XCDR2 between writer and reader |

`writer.matched_reader_count()` stays at 0 while no reader matches, and
`writer.get_offered_incompatible_qos_status()` reports the incompatibilities.

### Type Mismatch

Both sides must be generated from the same IDL: the same fully qualified type
name (`interop::Message`), the same member names, types and order, and the same
`@key` members. The topic name is case-sensitive.

## Network Configuration

For cross-machine interop where multicast is not available, disable multicast
and list the peers explicitly (the address is the peer's `ip:port`, as in the
[Migration Guide](../migration-from-fastdds.md#43-unicast-peers-no-multicast)):

```rust
use hdds::{MulticastMode, Participant, TransportMode, TransportOptions};

let participant = Participant::builder("hdds_node")
    .domain_id(0)
    .with_transport(TransportMode::UdpMulticast)
    .with_transport_options(TransportOptions {
        multicast: MulticastMode::Disabled,
        ..Default::default()
    })
    .add_static_peer("192.168.1.100:7411")
    .build()?;
```

HDDS shared memory is negotiated between HDDS participants only; a pairing with
another vendor's endpoint uses UDP. `.shm_disable()` on the builder turns the
capability off entirely.

## Testing Interoperability

1. Start subscriber (any vendor)
2. Start publisher (different vendor)
3. Verify messages received
4. Check sequence numbers for gaps

```bash
# Run HDDS publisher
cargo run --bin hdds_publisher

# In another terminal, run the Fast DDS subscriber
./fastdds_subscriber
```
