# Hello World in TypeScript

The HDDS TypeScript SDK (`@hdds/client`) is a native FFI binding to the
`hdds-c` shared library via [koffi](https://koffi.dev/). There is no
WebSocket bridge and no serialization detour: `write()`/`take()` are one FFI
call each into `libhdds_c.so`, which talks UDP multicast RTPS to any DDS
peer.

**Time:** ~10 minutes
**Prerequisites:** Node.js >= 18, a built `libhdds_c.so`

## Step 1: Build hdds-c

The TypeScript SDK calls the native HDDS library directly. Build it first,
from the repository root:

```bash
cargo build --release -p hdds-c
# Linux:   target/release/libhdds_c.so
# macOS:   target/release/libhdds_c.dylib
# Windows: target/release/hdds_c.dll
```

## Step 2: Build the SDK

`@hdds/client` is not published to the npm registry: it is built from this
repository.

```bash
cd sdk/typescript
npm ci
npm run build
```

The SDK is a native binding, not a source-only package: `npm run build`
compiles the TypeScript sources with `tsc`. There is no `ts-node`/`tsx`
runtime step anywhere in this SDK's workflow -- samples and applications are
compiled, then run with `node`.

If the native library is not under `target/release/` or a system library
path, point the loader at it:

```bash
export HDDS_LIB_PATH=/path/to/hdds/target/release
```

## Step 3: Create the Publisher

Create `temperature_publisher.ts`:

```typescript
import { Participant, QoS, TransportMode, version } from "@hdds/client";

interface Reading {
  sensor: string;
  celsius: number;
  seq: number;
}

function sleep(ms: number): Promise<void> {
  return new Promise((resolve) => setTimeout(resolve, ms));
}

async function main(): Promise<void> {
  console.log(`HDDS ${version()} - publisher`);

  // Domain 39 is only an example (it keeps this sample off domain 0);
  // pick your own for a real deployment.
  const participant = Participant.create("ts_publisher", {
    domainId: 39,
    transport: TransportMode.UDP_MULTICAST,
  });

  const qos = QoS.reliable().transientLocal().historyDepth(10);
  const writer = participant.createWriter<Reading>("temperature", qos);

  // Give discovery a moment before the first sample.
  await sleep(300);

  console.log("Publishing temperature readings...");

  for (let seq = 0; seq < 10; seq += 1) {
    const reading: Reading = {
      sensor: "sensor-001",
      celsius: 22.0 + seq * 0.5,
      seq,
    };
    writer.writeJson(reading);
    console.log(`Published: ${JSON.stringify(reading)}`);
    await sleep(1000);
  }

  participant.dispose();
}

main();
```

:::caution JSON serialization
`writeJson()` and `takeJson()` use JSON encoding, which is **not**
CDR-compatible. This works for TypeScript-to-TypeScript communication. For
cross-language interop with C/C++/Python, use types generated by `hddsgen`
(see [Typed Samples](#typed-samples)), or `write()`/`take()` with CDR2 buffers
you serialize yourself.
:::

## Step 4: Create the Subscriber

Create `temperature_subscriber.ts`:

```typescript
import { Participant, QoS, WaitSet, TransportMode, version } from "@hdds/client";

interface Reading {
  sensor: string;
  celsius: number;
  seq: number;
}

function main(): void {
  console.log(`HDDS ${version()} - subscriber`);

  const participant = Participant.create("ts_subscriber", {
    domainId: 39,
    transport: TransportMode.UDP_MULTICAST,
  });

  const qos = QoS.reliable().transientLocal().historyDepth(10);
  const reader = participant.createReader<Reading>("temperature", qos);

  const waitset = new WaitSet();
  waitset.attachReader(reader);

  console.log("Waiting for temperature data...");

  const deadline = Date.now() + 30_000;
  while (Date.now() < deadline) {
    if (!waitset.wait(5.0)) {
      console.log("No data received in 5 seconds, stopping.");
      break;
    }
    for (;;) {
      const reading = reader.takeJson<Reading>();
      if (reading === null) break;
      console.log(`Received: ${JSON.stringify(reading)}`);
    }
  }

  waitset.dispose();
  participant.dispose();
}

main();
```

## Step 5: Run

Samples are compiled, never run through `ts-node` or `tsx` (this SDK does not
take that dependency). The simplest way to build a new file against
`@hdds/client` is to drop it next to the SDK's own samples, which already
have a working `tsconfig` pointed at them (the file names below keep clear of
the SDK's own `publisher.ts` and `subscriber.ts`):

```bash
cp temperature_publisher.ts temperature_subscriber.ts sdk/typescript/samples/
cd sdk/typescript
npm run build            # compiles src/ -> dist/  (the package itself)
npm run build:samples    # compiles samples/ -> dist-samples/
```

Then, in two terminals, from `sdk/typescript`:

```bash
# Terminal 1
HDDS_LIB_PATH=/path/to/hdds/target/release node dist-samples/temperature_subscriber.js

# Terminal 2
HDDS_LIB_PATH=/path/to/hdds/target/release node dist-samples/temperature_publisher.js
```

For a real application outside this repository, depend on `@hdds/client`
from the tarball built by `npm pack` in `sdk/typescript`, and compile with
whatever `tsconfig` your own project uses -- `@hdds/client` ships its own
type declarations (`dist/index.d.ts`).

## Single-File Example (Intra-Process)

For a quick test without networking, publish and subscribe in the same
process using `TransportMode.INTRA_PROCESS`. This mirrors the SDK's own
`sdk/samples/12_typescript/hello_world.ts`:

```typescript
import { Participant, QoS, WaitSet, TransportMode, version } from "@hdds/client";

const TOPIC = "hello_world";
const COUNT = 5;

function main(): number {
  console.log(`HDDS ${version()} - hello_world`);

  const participant = Participant.create("hello_world_ts", {
    transport: TransportMode.INTRA_PROCESS,
  });

  try {
    const qos = QoS.reliable().transientLocal().historyDepth(COUNT + 5);
    const writer = participant.createWriter(TOPIC, qos);
    const reader = participant.createReader(TOPIC, qos);

    const waitset = new WaitSet();
    waitset.attachReader(reader);

    for (let i = 0; i < COUNT; i += 1) {
      const payload = `hello ${i}`;
      writer.write(Buffer.from(payload));
      console.log(`sent    ${payload}`);
    }

    const received: string[] = [];
    const deadline = Date.now() + 10_000;
    while (received.length < COUNT && Date.now() < deadline) {
      if (waitset.wait(1.0)) {
        for (;;) {
          const sample = reader.take();
          if (sample === null) break;
          received.push(sample.toString());
          console.log(`received ${sample.toString()}`);
        }
      }
    }

    waitset.dispose();
    console.log(`Done: ${received.length}/${COUNT} samples`);
    return received.length === COUNT ? 0 : 1;
  } finally {
    participant.dispose();
  }
}

process.exit(main());
```

The full, gate-tested version of this sample lives at
`sdk/samples/12_typescript/hello_world.ts`; build and run it directly with:

```bash
cd sdk/typescript
npm ci && npm run build && npm run build:samples
HDDS_LIB_PATH=/path/to/hdds/target/release node dist-samples/hello_world.js
```

## Typed Samples

For samples that other DDS implementations can read, define the type in IDL and
generate the TypeScript module with `hddsgen` 2.0 or later. It is installed from
its own repository (see [Installing hdds_gen](../tools/hdds-gen/installation.md)):

```bash
git clone https://git.hdds.io/hdds/hdds_gen.git
cargo install --path hdds_gen     # installs `hddsgen` into ~/.cargo/bin

hddsgen gen typescript temperature.idl -o temperature.ts
```

(The `hddsgen` release on crates.io stops at 1.0.12: do not use it.) For
`struct Temperature { @key unsigned long sensor_id; float value; unsigned long long timestamp; };`
the module exports the interface `Temperature` (a 64-bit field is a `bigint`),
`encodeTemperature()`, `decodeTemperature()`, `decodeTemperatureByEncapsulation()`
and `extensibilityTemperature`. Pass the module as the codec argument of
`createWriter()` and `createReader()`:

```typescript
import { Participant, QoS, TransportMode } from "@hdds/client";
import * as Types from "./temperature.js";

const participant = Participant.create("typed_demo", {
  transport: TransportMode.INTRA_PROCESS,
});
const qos = QoS.reliable().transientLocal().historyDepth(10);

// The generated module is passed as the codec: it names the type's
// extensibility (writer) and the encodings its decoders read (reader).
const writer = participant.createWriter<Types.Temperature>("temperature", qos, "Temperature", Types);
const reader = participant.createReader<Types.Temperature>("temperature", qos.clone(), "Temperature", Types);

writer.writeTyped({ sensor_id: 1, value: 23.5, timestamp: 0n });

const sample = reader.takeTyped(Types.decodeTemperatureByEncapsulation);
if (sample !== null) {
  console.log(`sensor ${sample.sensor_id}: ${sample.value}`);
}

participant.dispose();
```

Place the generated `temperature.ts` and this program in `sdk/typescript/samples/`
and build them as in Step 5.

## QoS Configuration

The SDK provides a fluent builder API for QoS:

```typescript
import { QoS } from "@hdds/client";

// Reliable with deadline and partitioning
const qos = QoS.reliable()
  .transientLocal()
  .historyDepth(10)
  .deadlineMs(500)
  .partition("sensor_data")
  .livelinessAutomatic(5.0);

// Inspect QoS settings
console.log(qos.isReliable());      // true
console.log(qos.getHistoryDepth()); // 10

// Clone for reuse (writer and reader need separate instances)
const readerQos = qos.clone();

// Reliable, Volatile, KeepLast(10) preset
const rtiQos = QoS.rtiDefaults();
```

## Error Handling

Native calls that fail raise `HddsError`, which carries the numeric code
from the C library:

```typescript
import { HddsError, Participant } from "@hdds/client";

try {
  const p = Participant.create("test");
} catch (e) {
  if (e instanceof HddsError) {
    console.error(`HDDS error [${e.code}]: ${e.message}`);
  }
}
```

## Architecture

```
Node.js Application
      |
      | @hdds/client (koffi FFI)
      v
+----------------+
|   libhdds_c    |  Native shared library
+----------------+
      |
      | UDP Multicast / RTPS
      v
+----------------+
|  DDS Domain    |  Other DDS peers (any vendor)
+----------------+
```

The SDK loads the hdds-c shared library at runtime and calls C functions
directly; no intermediate bridge process is needed.

:::tip Browser support
The native FFI SDK is Node.js only. Browsers cannot load a shared library
(`libhdds_c.so`), so browser applications go through `hdds-ws`, a Rust
WebSocket server that owns the DDS participant and speaks a JSON protocol.
`sdk/samples/12_typescript/ws_bridge.ts` is a dependency-free client for it.
:::
