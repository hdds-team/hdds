# Signed-document test fixtures

Consumed by `crates/hdds/src/security/test_pki.rs` through `include_bytes!`, so
the tests stay hermetic: no file is read from outside the crate at run time.

## HDDS-generated material

Everything except the `fastdds_*` files is produced by
`scripts/security/gen-signed-fixtures.sh` (openssl 3.5.6). The script is never
run by a test; regenerate by hand and commit the result.

The CA private keys are deliberately NOT committed: a fixture is only ever
regenerated as a whole set. The `*_keyid.*` files have their own CAs so that
section can be regenerated on its own without moving any other fixture. Certificates are valid until 2036 except
`expired_perm_ca.pem`, which is expired on purpose.

| file | what it proves |
| --- | --- |
| `perm_ca_ec.pem` | EC P-256 permissions CA, the primary trust anchor |
| `perm_ca_rsa.pem` | RSA-2048 permissions CA (RSA branch of the OID map) |
| `other_perm_ca.pem` | an unrelated CA; its documents must be refused |
| `expired_perm_ca.pem` | expired CA; its documents must be refused |

| `governance_ec.smime`, `permissions_ec.smime` | valid S/MIME multipart/signed |
| `permissions_rsa.smime` | valid, RSA-2048 signer |
| `permissions_ec_no_subheaders.smime` | valid, first part carries no MIME sub-headers |
| `permissions_ec_attached.p7s` | valid DER PKCS#7 with eContent present |
| `permissions_ec_detached.p7s` | DER PKCS#7 without eContent (no document) |
| `permissions_tampered.smime` | valid signature, edited XML body |

| `other_perm_ca_keyid.pem`, `permissions_other_ca_keyid.smime` | a foreign key identifier, which that path must refuse |
| `audit_governance.xml` / `.smime` | domain 229 rules for the audit end-to-end test |

| `pss/differential.txt` | differential vectors for the same verifier, by `scripts/security/gen-pss-differential.py` (python-cryptography 43.0.0 on OpenSSL 3.5.7, never run by a test): 14 RSA keys of 1024 to 4097 bits, exponent 65537 or 3, 24 cases each, every salt length, at most one defect per case (EMSA-PSS field, signature, message, hash or MGF); the verdict is OpenSSL's with `salt_length=PSS.AUTO`, and a refusal for a key outside 2048..=8192 bits |
| `governance_spec_example.xml` | the example governance document of DDS-Security v1.1 Sec.9.4.1.2.8, unsigned, with the two repairs its header names; hand-written, not generated |

## Third-party material

`fastdds_permissions.smime`, `fastdds_maincacert.pem`,
`fastdds_permissions_other_ca.smime` and `fastdds_othercacert.pem` are verbatim
copies of eProsima Fast DDS test material
(`test/certs/permissions.smime`, `test/certs/maincacert.pem`,
`test/certs/permissions_helloworld_securehelloworld_other_ca.smime`,
`test/certs/othercacert.pem`), Copyright eProsima, licensed under the
Apache License 2.0. They serve as an INDEPENDENT oracle: a signed permissions
document HDDS did not produce, verified by `openssl smime -verify` on the same
box, must also verify in `security::cms`.

`fastdds_maincacert.pem` expires on 2027-09-04, so every test that uses it
passes an explicit fixed `now` rather than the wall clock.
